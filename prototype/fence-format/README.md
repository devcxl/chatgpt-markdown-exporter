# 围栏消息块 · 格式原型（一次性，不进 master）

这是 issue [#30](https://github.com/devcxl/chatgpt-markdown-exporter/issues/30) 的探针，用来回答一个视觉问题：**把每条消息渲染成围栏代码块，到底长什么样更好？**

不是实现方案，也不是最终格式；代码不会合进 `master`。

## 怎么看

- 打开 `index.html`：四种格式并排渲染（无网络依赖，直接双击即可）
- 用 **Obsidian / Typora / VS Code 内置预览** 打开同目录的四个 `.md`：这才是文件真正的归宿，值得对照

## 四种格式

| 文件 | 围栏标识 | 角色名与时间的位置 |
|---|---|---|
| `variant-a-text-inline.md` | `text` | 块内第一行 |
| `variant-b-ascii-role.md` | `User` / `ChatGPT` / `Plugin`（英文，不随 locale 变） | 块内第一行（本地化） |
| `variant-c-heading-outside.md` | `text` | 块外 `###` 标题 |
| `variant-d-keep-heading.md` | `text` | 块外 `---` + `##` + `> 时间`（即现状，只把正文代码块化） |

四种都渲染**同一段对话**，并且刻意包含三个难点：

1. 用户消息里嵌了 ` ```ts ` 代码块 → 外层必须用 4 个反引号
2. 助手消息含有序列表与行内代码
3. 插件消息含 ` ```json `，且作者名带空格：`Plugin (browser)`

## 需要你判断的

1. 哪种读起来最舒服？——这是唯一必须你回答的问题
2. 围栏把**图片、引用链接、脚注**也变成纯文本了（代码块内不渲染），这个代价能接受吗？如果不能，D 也是同样问题，只有「围栏只包裹正文」能缓解
3. 时间戳在块内（A/B）时会是代码内容的一部分，复制粘贴会带上；可接受吗
4. 默认关还是默认开

## 已知不在这份原型里

- 围栏长度算法（正文最长反引号 + 1）只在这里手写演示，真实实现要进 `renderMessageBlock()`
- 选项如何传到页内按钮（当前是硬编码的一套值）
- frontmatter 统计口径会随格式变化漂移，属另一项决策
