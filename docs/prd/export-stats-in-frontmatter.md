# PRD：Markdown Frontmatter 导出统计信息

- 状态：已确认（2026-07-31）
- 需求来源：用户反馈（长篇虚构小说作者，使用 ChatGPT 作为语法助手与进度监督员）

## 背景

用户反馈摘录：

> 特别喜欢顶部的信息栏，一目了然，而且能按聊天真实名称保存文件……但要是能再加个字数统计、行数统计或者消息条数统计，那就更完美了。
>
> 我平时写长篇虚构小说，拿 ChatGPT 当语法助手和进度监督员，这个功能让我能把当天即兴聊过的所有对话一次性下载下来。

用户每天批量导出对话存档，希望在导出的 Markdown 顶部信息栏中直接看到对话规模统计（字数/行数/消息条数），用于快速了解当天工作量和检索定位。

## 目标

在导出的 Markdown **frontmatter 区**新增三个统计字段：

| 字段 | 含义 |
|---|---|
| `word_count` | 正文字数（英文按单词数，中文按字符数） |
| `line_count` | 正文行数 |
| `message_count` | 消息条数（用户 + 助手消息，不含系统/工具消息） |

统计对象为**导出正文**（不含 frontmatter 本身），与用户实际看到的 Markdown 内容一致（即经过 `shouldSkipMessage` 过滤后的内容）。

## 非目标

- 不做按日期筛选/批量按天导出（维持现状，用户明确暂缓）
- 不改动导出面板 UI（统计信息只进 frontmatter）
- 不新增单独的统计报告或图表

## 需求详述

### 1. 字数统计（word_count）

- **英文/数字**：按单词数统计（空格分隔的连续非空白字符序列计 1 个单词）
- **中文**：按字符数统计（每个汉字计 1 字，中文标点不计）
- **混合内容**：中文字符数 + 英文单词数（分别统计后相加）

> 口径细节（如标点、URL、代码块处理）由技术方案最终确定，但必须满足"英文按单词、中文按字符"的核心约定。

### 2. 行数统计（line_count）

- 导出正文的总行数（按 `\n` 分割）

### 3. 消息条数统计（message_count）

- 统计最终渲染进 Markdown 的消息条数（与 `shouldSkipMessage` 过滤逻辑一致）
- 用户（`user`）+ 助手（`assistant`）消息都计入；系统/工具消息不计入
- 推荐口径：与导出内容中实际出现的消息块数量一致，保证"数字 = 看到的条数"

## 验收标准

1. 导出的 Markdown frontmatter 中新增 `word_count`、`line_count`、`message_count` 三个字段
2. 纯英文文本：`word_count` = 单词数；纯中文文本：`word_count` = 汉字数
3. `line_count` 与正文实际行数一致
4. `message_count` 与导出的消息块数一致（系统/工具消息不计）
5. 关闭 frontmatter 选项（`includeFrontmatter: false`）时不受影响
6. 现有导出功能（批量 ZIP、文件名、内容格式）行为不变
